# Building and testing

Requirements: Node 22+, and `ffmpeg`/`ffprobe` on `PATH` for the fixture tests.

```sh
npm ci
npm --prefix packages/protected-packet-core ci
npm test               # extension + schema tests (node --test)
npm run test:packet    # protected packet core
npm run build          # build/extension/candidate-*/ plus a build-report.json
```

Load the candidate folder in `chrome://extensions` with Developer mode on ("Load unpacked"). A local build gets its own extension ID; the Chrome Web Store assigns the published one.

## Checking a build against the store

The build is reproducible. `npm run build` prints an `artifactSha256`, a hash over every file in the package, and `node scripts/build-extension.mjs --verify <folder>` recomputes it from a folder on disk. The package submitted to the Chrome Web Store for a version has the same value.

An installed copy from the store is not byte-identical: the store adds its own files (a `_metadata/` folder) and fields such as `update_url` to `manifest.json`. To check one, compare its other files with your build's, file by file. Compare files, not ZIP archives, which carry timestamps.

The build is the store's viewer edition (`--viewer`). The scripts accept other options used in development, but the files for them are not in this repository.

## The protected bundle

`packages/browser-extension/vendor/protected/owner.mjs` and `signout.mjs` are generated by esbuild (pinned in `devDependencies`) from `packages/protected-packet-core/client` and the extension's own `src` modules. `PROVENANCE.json` records the esbuild version, every input's SHA-256 and the output hashes. Paths inside the bundle are normalised, so it is byte-identical wherever it is built.

```sh
npm run check:protected   # rebuild in memory; fails if the committed bundle is stale
npm run build:protected   # regenerate after changing one of its inputs
```

The extension build also refuses a bundle whose recorded inputs no longer match the sources.

## Edit rules

`packages/browser-extension/rules/seamless-rules-v1.json` is the single source for the edit limits the extension enforces. `npm run build:rules` regenerates `src/seamless-rules.mjs`, the edit-pack schema and the boundary test vectors; `npm run check:rules` fails if any is stale.

## Line endings

`.gitattributes` keeps LF checkouts on every OS. The build hashes source files, so a CRLF conversion would fail its checks.
